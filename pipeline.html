Pipeline

Take IOM evaluation reports from PDF to SRF and GCM mappings, saving the state at each stage

A Report takes an evaluation through four stages:

  1. Download. download fetches the evaluation’s documents from the IOM repository.
  2. OCR. ocr converts the report PDF to Markdown pages, with fixed heading levels.
  3. Curation. A person selects the report’s core sections in the curator app (06_curator.ipynb).
  4. Mapping. The map_* methods score the core sections against the themes of the Strategic Results Framework (SRF) and the Global Compact for Migration (GCM).

run_pipeline runs the stages for one evaluation, and batch_run for many.

Report class

A Report wraps an Evaluation, with the state of each stage: pdf_path, md_path, curation_status, selected_headings and mappings. Creating a Report loads the saved state from results_path, when there is one.

Note

from_title and from_id find the report among the evaluation’s documents with eval_url. An evaluation’s documents can also include a brief, annexes and a management response. They raise ValueError when eval_url finds no report.

Persistence

save writes a report’s state to results_path/<id>.json. The file holds the evaluation, the report URL, the curation status, the selected headings, the mappings and a timestamp. ocr, each map_* method and run_pipeline save the report after they run. download does not. load_report reads the state back from a base folder, which holds the pdf/, md/ and results/ folders. It sets pdf_path and md_path to the report’s folders under pdf/ and md/, when they exist.

Pipeline methods

Run the methods in stage order. download comes first, then ocr, then the map_* methods once the report is curated.

Download

download saves every document of the evaluation in dst/<id>/ with download_eval, and sets pdf_path to that folder. It does nothing when pdf_path is already set, unless force is true.

OCR

ocr converts the report PDF to Markdown pages in dst/<id>/ with mistocr’s pdf_to_md. mistocr OCRs the PDF with Mistral and fixes the heading levels with an LLM. With add_img_desc, it also adds a description of each image. The PDF is the file named after pdf_url in pdf_path, or the first PDF there when pdf_url is not set. ocr does nothing when dst/<id>/ exists, unless force is true.

Curate

A person reviews the OCR’d headings and selects the core sections in the curator app (06_curator.ipynb). The app then sets curation_status to 'sections_selected' and saves the headings in selected_headings.

Thematic mapping

Each map_* method maps the selected sections against one theme set, and saves the report. You can run each one on its own after curation. A method skips a theme set that is already in mappings, unless force is true. ensure_sp builds the report system prompt from the selected sections once, and the later mappings reuse it.

Run the full pipeline

run_pipeline takes one evaluation, found by url, id or title, as far through the stages as it can. It first loads the report’s saved state from base_path, and it skips the stages already done. It returns a PipelineResult with one of three statuses:

  • 'awaiting_curation' when the report still needs curation. Curate it in the curator app, then run the same call again.
  • 'completed' after the four mappings.
  • 'failed' when a stage raises an error. run_pipeline logs the error, and the result holds its message in error and the stage in step.

Errors raised while creating the report, such as a missing report URL, are not caught. force runs stages again. Pass True for every stage, or a set of step names such as {'ocr', 'gcms'}. The step names are 'download', 'ocr', 'enbs', 'ccps', 'gcms' and 'outs'. By default, run_pipeline deletes the PDF folder after OCR.

Batch

The IOM repository export, from evaluation-search-pdf, lists each evaluation’s documents with their type, such as brief, annex or final report. The types and URLs do not always match. A URL labelled “Evaluation Report” can point to an annex or a brief. IOM knows about this bug and is fixing it.

As a workaround, IOMRepoReader.to_json gets each evaluation’s report URL from IOM’s UNEG API, /json/api/evaluation-uneg. It adds that URL as the evaluation’s first document, with subtype 'Evaluation report (UNEG)', and eval_url prefers it. The UNEG API has less metadata than the export.
