Mapper

Score how relevant an evaluation report is to each SRF and GCM theme, with an LLM

The mapper scores a report against four theme sets: the SRF enablers, the SRF cross-cutting priorities, the GCM objectives and the SRF outputs. For each theme, the LLM returns a relevance score from 0 to 1 and its reasoning. The report is the same for every theme set, and prompt caching lets the calls after the first reuse it.

from cachy import enable_cachy
enable_cachy()

Response models

The LLM replies with a ThemeScores, which holds one ThemeScore per theme. structured_llm sends each model’s docstring to the LLM as part of the reply format.

Parsing

parse_res turns a reply into a list of score dicts, the form the pipeline saves. sort_by_relevance orders the scores from most to least relevant. get_top_ids keeps the IDs of the themes that score at least min_score, 0.66 by default.

Mapping a report

map_themes asks the LLM to score one set of themes against a report. mk_system_prompt puts the report in the system prompt. map_themes marks that system prompt for prompt caching with cache_idxs=[0]. The later mappings of the same report read it from the cache, which costs less than sending it again.

Mapping against every framework

map_all maps a report against the SRF enablers, the cross-cutting priorities and the GCM objectives. It then maps the SRF outputs linked to the top GCM objective, which it looks up with get_srf_outs. When no GCM objective reaches the get_top_ids threshold, it maps no outputs and returns outs=None. The four calls share the cached report. Report.map_all in the pipeline runs the same steps and saves each result.
